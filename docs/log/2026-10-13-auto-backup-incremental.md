# Automatic backups: pictures once, no thumbnails, failure notice (D-043)

- Date: 2026-10-13 · Thread/agent: coordinator worker W2 (fix-auto-backup)
- What changed: Desktop automatic backups now store each picture once as `backups/images/` (file named after the SHA-256 of its bytes) and the day file (format version 2) only points at it; only new pictures are written, unreferenced picture files are removed after pruning to seven days, and the picture database is read a few records at a time with pauses (no single giant string). Thumbnails are left out of automatic backups (restore clears them and the app makes them again); `clipbox.account-premigration.v1` is left out of every backup and dropped from older files on restore; a failed run is remembered in `clipbox.auto-backup.last-error` and shown in 设置 → 数据 until the next success. Version 1 files (pictures inside) still restore; the browser trial keeps writing version 1. Four new Rust commands in `src-tauri/src/backup.rs` (+ bridge.js, desktop-bridge.ts types), with Rust unit tests.
- User-visible change (plain Chinese, for the preview changelog): 每天自动备份不再每天把全部图片复制一遍，只存新加或改过的图片，备份时界面不卡；备份失败会在设置里说明；开启账号加密前留的那份旧数据不再放进备份。
- Not done / risks: Not run in the real Tauri app on Windows or macOS (cargo test passes; the commands were exercised through a fake bridge in e2e). The 完整备份 file is still one sealed JSON string, so its size limit (a few hundred MB of pictures) is unchanged. An app version older than this one cannot restore a version 2 automatic file (it refuses it as "not a Clipbox backup").
- Next step: On Windows: let a day's backup run with a few pictures, check `backups/images/` in the data folder, restore a day from 设置 → 从自动备份恢复, and check the pictures and their thumbnails come back.
