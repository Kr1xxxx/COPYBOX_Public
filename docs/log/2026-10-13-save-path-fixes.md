# Save path fixes: quit by ×, restore vs. pending saves, cached keys, storage full

- Date: 2026-10-13 · Thread/agent: coordinator worker W1 (fix-save-path)
- What changed: With 「关闭即退出」 the × button no longer destroys the window before the page could save: `shell.rs` hides the window and quits through `Shell::quit` (exit request → page flush, 1.5 s timeout unchanged), and the page's flush handler now also waits for the 账号 store queues (`store-queue.ts` `drainAll`) and image writes (`image-store.ts` `waitForImageWrites`). A full restore (`applyPayload`) first saves everything pending and then closes a write gate (`app/write-gate.ts`): the vault and the 账号 stores refuse to write until the page reloads, so a delayed save can no longer land on the restored data with the old key; a restore that fails and rolls back reopens the gate. PBKDF2-derived keys are cached in memory (`app/key-cache.ts`) and the 账号 stores keep their stored salt when rewriting (IV still random every write), so a save no longer runs 310 000 rounds; `bytesToBase64` in `page.tsx` works in 32 KB slices. A full localStorage (QuotaExceededError) now says 「存储空间满了，请清空回收站或删掉不用的内容」 in the editor and for delayed saves, and a save that leaves clipbox.* storage above 85 % of 5,000,000 characters warns once per session.
- Storage format: unchanged. Same keys, same envelope fields, same PBKDF2-SHA-256 310 000 rounds and AES-GCM; only the 账号 envelopes now keep their salt between rewrites (the vault already did). Old envelopes open with the new code and new ones with the old code (tests/key-cache.test.mjs).
- User-visible change (plain Chinese, for the preview changelog): 点 × 关闭也会先存好再退出；从备份恢复时不会被刚才的操作覆盖；保存更快；存储快满或已满时会直接说清楚。
- Verification: lint and typecheck pass; npm test 419/419; `cargo test` in src-tauri 33/33 (Linux, with the GTK/WebKit dev packages installed and a placeholder dist-tauri); full Playwright suite 217 passed, 1 failed (list-ui-behaviour "starring a snippet…" animation timing, passed 3/3 alone and with its whole file afterwards). The new restore e2e test fails 3/3 with the gate removed (35 rows instead of the restored 34).
- Not done / risks: The Rust change was compiled and unit-tested on Linux only; the × → hide → quit path still needs a check on real Windows and macOS. If a restore fails AND its rollback fails, the gate stays closed until reload on purpose (the stored data is then in an unknown state). Image writes are waited for but not refused while the gate is closed. Backup passwords used for an export or import are kept as derived keys in memory for the session (at most 16 keys, never stored).
