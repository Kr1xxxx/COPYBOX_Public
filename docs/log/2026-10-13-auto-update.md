# Windows updates itself with a progress bar (D-047)

- Date: 2026-10-13 · Thread/agent: worker W15 (auto-update)
- What changed: The Windows app now checks https://copyboxx.com/download/latest.json (macOS and Linux stay off) and only accepts an https download on copyboxx.com. New command `update::install_update` streams the installer to the temp folder with progress events (`clipbox:update-progress`, at most ten a second), checks the exact size and the SHA-256 (Windows BCrypt, new `windows` feature flag `Win32_Security_Cryptography`, no new dependency), then quits the normal way so the page saves first and starts the installer with `/P /R /UPDATE` inside the flush callback. Bridge `installUpdate` and `onUpdateProgress` with types; the banner in `app/update-notice.tsx` gets 立即更新, a progress bar, the installing text and an error state with 重试 and 去网站下载; old shells keep 下载. `Shell::begin_quit` and `Shell::cancel_quit` split out of `quit`. Rust unit tests and e2e in `tests/e2e/update-notice.e2e.mjs`; the web preview shows no update notice (owner, 2026-10-14).
- User-visible change (plain Chinese, for the preview changelog): Windows 版有新版本时点「立即更新」，会显示下载进度条，下载完自动安装并重新打开，不用再去网站下载；没成功时会说明原因，可以重试或去网站下载
- Not done / risks: Only checked on Linux and in the browser. The Windows-only parts (BCrypt hashing, starting the installer detached, the installer's /P /R /UPDATE run over a running app, the app reopening) were type-checked for the Windows target but never run; CI's Windows `cargo test` runs the BCrypt test. Apps installed before this change need one manual install to get it. The first automatic update across a product rename installs beside the old app (D-044, D-047). The update only works once copyboxx.com is bound to the Worker (D-045).
