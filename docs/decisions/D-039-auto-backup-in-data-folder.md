### D-039 Daily automatic backup, kept in the data folder without a password (2026-10-12)
- Context: everything lives only in the app's own storage. Clearing it, reinstalling with "delete data", or a failing disk loses images and accounts, and the manual 完整备份 (the old 「导出到新版」 file) is easy to forget.
- Decision: 设置 → 数据 renames 「导出到新版」/「从旧版导入」 to 「完整备份」/「从完整备份恢复」 (same file format `clipbox-data-move` v1, password-sealed, restore asks again before replacing). A switch 「每天自动备份」 (on by default) saves one file a day, `clipbox-auto-YYYY-MM-DD.json`, holding the same records the app keeps (話術, 账号, 验证码, 图片, settings; already-encrypted stays encrypted), and keeps the newest seven. Desktop: `backups/` in the app data folder, written by `src-tauri/src/backup.rs` (three commands, fixed file-name shape, nothing outside that folder). Browser trial: simulated in its own storage key `clipbox.web-backups.v1`, which is never copied into a backup. 「从自动备份恢复」 lists the saved days, says what will be replaced, asks once more, and uses the same checked restore (a copy of the current data is kept until it finishes).
- Consequences: the automatic files have no password, so they are as protected as the data folder itself (the device key is in the same place, see D-038); the privacy note in 设置 says so, and says to use the password-sealed 完整备份 when a copy leaves the computer. They do not protect against losing the whole disk; that still needs a manual 完整备份 kept elsewhere. No storage key or encryption format of existing data changes. New pref key `clipbox.auto-backup.enabled`.
- Status: Accepted (owner picked advisor item 1 on 2026-10-12).
