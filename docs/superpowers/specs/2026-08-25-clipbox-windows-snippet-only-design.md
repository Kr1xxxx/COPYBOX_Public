# Clipbox Windows 纯话术版设计规格

## 目标

在不改变现有 macOS Clipbox 行为、界面和数据的前提下，交付 Windows 10/11 x64 的 Clipbox 安装版。Windows 版只提供话术管理，不显示、创建、保存或导出秘密；首次启动为空，用户只能通过导入现有 Clipbox 加密备份或手动新增来建立话术库。

最终产物是 NSIS 安装包 `.exe`，不提供便携版。

## 产品边界

### macOS

- 保持现有“秘密 + 话术”双板块产品不变。
- 保持现有秘密、话术、目录、搜索、复制、备份导入与导出行为不变。
- 保持现有 macOS 打包方式和应用数据不变。

### Windows

- 仅支持话术，不提供秘密功能。
- 首次启动不包含示例话术或其他预置内容。
- 用户可以重复导入 Clipbox 加密 JSON 备份，也可以手动新建、编辑和删除话术。
- 用户不能导出任何数据，包括在 Windows 上手动新建或修改的话术。
- 不提供 Excel、CSV 或其他新导入格式。
- 支持 Windows 10/11 x64，不提供 ARM64 或便携版。

## 架构

采用同一代码库、运行时按平台能力切换的方案。业务逻辑、加密格式、搜索、目录、复制和备份解密继续共享；平台差异集中在 Electron 壳层、preload 能力声明、界面入口和导入过滤。

Electron preload 通过只读、安全的桥接接口向渲染进程暴露产品能力。macOS 为完整版本，Windows 为 `snippet-only`。渲染进程根据能力决定可见功能和允许的数据类型，而不是复制一套 Windows 页面。

现有双类型数据模型继续保留，以保证 macOS 保险库和历史备份兼容。Windows 在载入、导入和写入边界都执行纯话术过滤，防止秘密通过旧数据、混合备份或异常状态进入 Windows 保险库。

Windows 和 macOS 使用各自操作系统的 Electron 应用数据目录。Windows 版本不会读取、迁移或修改 macOS 本地应用数据；跨平台迁移只能通过现有加密 JSON 备份完成。

## Windows 界面与交互

- 左侧不显示“秘密 / 话术”切换。
- 左侧顶部直接显示“话术库”和话术总数，下方保留全部、置顶、目录和未分类。
- 设置区域只保留“导入话术备份”，不显示导出入口。
- 首次启动显示空状态，并提供“导入 Clipbox 备份”和“新建话术”两个主要操作。
- 新建和编辑弹窗固定为话术，只包含标题、目录、话术内容和总结。
- 保留现有搜索、方向键选择、Enter 复制、置顶、目录、最近使用排序和复制反馈。
- Windows 使用原生标题栏和系统窗口按钮，不显示 macOS 交通灯或重复的应用内标题栏。
- 关闭主窗口时应用驻留系统托盘；托盘菜单提供快速搜索、打开 Clipbox 和退出。
- 全局快速搜索快捷键为 `Ctrl+Alt+Space`，避免占用 Windows 的 `Alt+Space` 窗口菜单。
- 从快速搜索窗口复制后，继续按现有逻辑自动收起窗口。

## 数据流

### 首次启动

Windows 首次启动时使用现有设备密钥与加密流程创建空的本地保险库。保险库中只有空的话术集合和空的话术目录，不生成示例条目。

### 手动新增与编辑

Windows 创建或更新条目时，条目类型固定为 `snippet`。保存前通过纯话术边界校验，随后使用现有 AES-256-GCM 保险库流程写入本地数据。

### 导入

导入流程保持“先完整验证、再写入”的安全边界：

1. 读取并解析现有 Clipbox 加密 JSON 备份。
2. 验证文件格式并使用备份密码解密。
3. 规范化历史和当前保险库数据结构。
4. 仅保留 `kind: "snippet"` 的条目及话术目录，统计被跳过的秘密条目数量。
5. 按用户选择执行合并或覆盖。
6. 再次执行纯话术校验后加密写入 Windows 本地保险库。
7. 显示结果，例如“已导入 24 条话术，跳过 3 条秘密”。

合并沿用现有同类型、同标题、同内容去重规则。覆盖只使用过滤后的话术数据替换当前 Windows 话术库；备份中的秘密不会保留。

### 导出

Windows 版不渲染导出入口，不开放导出流程，也不提供替代导出方式。此限制覆盖导入的话术以及用户在 Windows 上新建或修改的话术。

## 错误处理

- 无法解析的文件提示“这不是有效的 Clipbox 加密备份”，不改变现有数据。
- 备份密码错误或密文损坏时提示验证失败，不改变现有数据。
- 备份没有任何话术时明确提示没有可导入的话术；合并模式不写入，覆盖模式也不清空当前话术库。
- 导入成功时同时报告导入话术数量和跳过秘密数量。
- 本地服务启动失败沿用现有错误对话框并安全退出。
- 全局快捷键注册失败不阻止应用启动；托盘和窗口内搜索仍可使用。

## 打包与发布

- 保留现有 macOS 构建脚本和配置。
- 新增独立的 Windows x64 构建脚本。
- 使用 electron-builder 的 Windows NSIS 目标生成安装包 `.exe`。
- 使用现有 Clipbox 品牌图标生成 Windows `.ico` 资源，不重新设计品牌标识。
- 默认按当前用户安装，不要求管理员权限。
- 安装后创建规范的开始菜单入口，并支持正常卸载。
- 不构建便携版或 Windows ARM64 版本。

## 测试与验收

### 自动化测试

- 平台能力：macOS 为完整版本，Windows 为 `snippet-only`。
- Windows 数据过滤：载入、导入、合并、覆盖和保存边界均不会保留秘密。
- 混合备份：只导入话术并正确统计跳过的秘密。
- 空备份：没有话术时不覆盖或清空当前 Windows 数据。
- Windows 界面：不显示秘密切换、秘密编辑控件或导出入口。
- Windows 空状态：显示导入与新建两个入口。
- macOS 回归：仍显示秘密与话术，并保留导入和导出能力。
- 现有核心测试、渲染测试、构建、lint 和类型检查继续通过。

### 桌面与安装包验证

- Windows x64 NSIS 安装包成功生成。
- 安装、启动、关闭到托盘、托盘重新打开和卸载行为正常。
- `Ctrl+Alt+Space` 能打开快速搜索；快捷键不可用时应用仍可正常启动。
- 首次启动为空，手动新增、搜索、复制、编辑和删除可用。
- 混合 macOS 备份能够导入话术并跳过秘密。
- Windows 界面和文案中不存在可操作的秘密或导出功能。
- macOS 现有桌面构建和产品行为没有回归。

## 非目标

- 不重新设计 Clipbox 品牌或整体界面。
- 不重写为 .NET、WPF、WinUI 或 Tauri 应用。
- 不加入云同步、账号、远端数据库或自动更新。
- 不加入 Excel、CSV、纯文本或剪贴板批量导入。
- 不提供 Windows 数据导出、便携版、ARM64 或安装范围选择。
