# Clipbox 双 Skill 视觉概念设计规格

## 目标

基于当前 Clipbox `680 × 620` 的真实信息架构，分别使用 Taste Skill 与 Open Design 生成一张可直接比较的主页设计图。此轮只输出静态视觉稿，不修改应用代码、数据结构或功能逻辑。

## 当前界面审计

- 保留：原生标题栏、秘密与话术切换、目录、搜索、条目列表、置顶、复制、左下设置和右下新增。
- 保留：适合缩小使用的紧凑窗口、十字以内话术总结、秘密与话术的语义区分。
- 优化：减少空状态和列表中的无效留白，强化目录层级与快速复制路径。
- 优化：统一文字、间距、圆角、分隔线和反馈状态，避免松散的大卡片布局。
- 不变：标题栏结构、功能名称、交互位置和主要操作顺序。

## 交付形式

- Taste Skill 方案 PNG：`1360 × 1240`，对应 `680 × 620 @2x`。
- Open Design 方案 PNG：`1360 × 1240`，对应 `680 × 620 @2x`。
- 每个方案附一份视觉哲学 Markdown 文件。
- 两张图均展示“话术”主页，使用相同示例数据，便于比较总结、目录、置顶和复制状态。
- 不生成 PDF，不修改现有 App 源码。

## 统一示例内容

- 当前板块：话术。
- 当前目录：售后。
- 搜索框：搜索话术或总结。
- 条目：售后夸赞、物流延迟、护理提醒、补发确认、回访邀请。
- 每条展示标题与不超过十字的总结。
- “售后夸赞”展示置顶状态，“物流延迟”展示已复制反馈。

## 方案一：Taste Skill

### Design Read

Reading this as: a compact desktop utility for a solo power user, with an editorial utility language, leaning toward a flat ledger layout and restrained physical feedback.

Taste Skill 明确不以密集产品 UI 为主要适用范围，因此本方案只采用其反模板、设计判断、版式、色彩锁定和预检原则，不套用营销页 Hero 或展示型结构。

### 参数

- `DESIGN_VARIANCE: 5`
- `MOTION_INTENSITY: 4`
- `VISUAL_DENSITY: 7`
- 模式：Redesign - Preserve。

### 视觉方向

- 名称：Editorial Utility。
- 深石墨目录栏与暖白主内容形成清晰分区。
- 单一琥珀强调色随当前“话术”状态使用，复制成功使用必要的语义绿色。
- 列表采用扁平账本结构，以留白、字体重量和细线建立层级，不使用悬浮大卡片。
- 目录更像书签索引，活动项通过背景和左侧短标记识别。
- 标题略具编辑感，但不牺牲小窗口可读性。
- 复制反馈靠近原按钮出现，状态清楚但不遮挡列表内容。

## 方案二：Open Design

### 视觉方向

- 名称：Calm Operational。
- 使用浅灰画布、白色内容面和克制的蓝紫强调色。
- 以设计 Token 明确表面、边框、文字、语义色、圆角和间距。
- 侧栏、搜索、列表、按钮和状态采用一致的组件规则。
- 列表更加标准化，标题、总结、置顶和复制操作使用稳定列位。
- 选中、悬停、已复制与空状态都具有明确且可访问的视觉反馈。
- 视觉更接近可直接实施的生产级桌面工具，方便长期维护。

## 两套方案的差异边界

- Taste Skill 重点体现版式个性、材质反差和紧凑账本感。
- Open Design 重点体现组件一致性、可访问性和落地稳定性。
- 两者使用相同内容、窗口尺寸和功能位置，差异来自视觉系统，而非改变产品结构。
- 两者都避免 AI 紫色渐变、玻璃卡片堆叠、过度圆角、装饰性状态点和无意义大留白。

## 视觉哲学文件

- Taste Skill：`design/concepts/taste-editorial-utility.md`。
- Open Design：`design/concepts/open-calm-operational.md`。
- 每份文件包含 4-6 段视觉哲学，指导画布中的空间、色彩、节奏、层级和细节工艺。

## 质量验证

- 检查两张 PNG 的实际尺寸均为 `1360 × 1240`。
- 在原尺寸 `680 × 620` 下检查文字可读性和按钮清晰度。
- 检查所有文字、图形和控件均在画布内，无重叠、裁切或溢出。
- 两张图使用相同示例数据和功能位置。
- Taste Skill 方案执行其颜色、形状、密度和反 AI 模板预检。
- Open Design 方案检查 Token、组件、层级、对比度和真实应用状态。
- 完成首稿后进行一次只做删减、对齐和间距精修的第二遍设计修订。
