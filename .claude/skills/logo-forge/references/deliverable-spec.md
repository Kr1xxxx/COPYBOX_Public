# Deliverable Spec — What a Complete Logo Set Contains

Read at Step 7, once a direction is chosen. This is the manifest `lf_export.py` and the final presentation should satisfy — treat missing items as a failed deliverable, not an optional nice-to-have.

## Master variants (SVG source, one file each)

- `primary.svg` — full combination mark (icon + wordmark together), the default lockup for most uses
- `icon.svg` — icon/symbol only, no text — this is what gets used at small sizes
- `wordmark.svg` — text only, no icon
- `monogram.svg` — initials-only variant, if applicable to the chosen direction

## Lockups

- `primary-horizontal.svg` — icon beside wordmark
- `primary-stacked.svg` — icon above wordmark
(Not every direction needs both — a wordmark-led mark may only need the horizontal.)

## Color variants (each of the above, in each of these)

- Full-color (the locked palette)
- Single-color black (must be legible with zero color — see design-principles.md §4)
- Reversed / single-color white (for dark backgrounds)

## Specs (one markdown file, `spec-sheet.md`)

- Minimum size (px, below which the mark shouldn't be used, and what to use instead — usually the reduced `icon.svg` or a purpose-drawn small-use variant)
- Clear space (expressed as a multiple of a feature of the mark itself, e.g. "clear space on all sides ≥ the height of the icon", so it scales with the mark)
- Locked palette (hex + a plain-language name for each color)
- Type family/families used, with the specific weight(s)
- One "don't" example category per common misuse (stretching, recoloring outside the locked palette, placing on a low-contrast background) — described in words, not full mockups, unless the person asks for the mockups too

## Application assets (generated by `lf_export.py`)

- Favicon: `favicon.ico` (multi-size container: 16/32/48px)
- Web PNGs: 32/64/128/256/512px, transparent background
- iOS app-icon size set (per current App Store icon size requirements — verify current required sizes if this matters for a real submission, they do change)
- Android adaptive-icon / mipmap size set
- Social profile-picture crop (square, safe-margin for circular crop) and a cover-image variant if requested

## Brand guideline doc (only if requested — don't default to producing a full PDF unless asked)

If the person wants the full guideline document (not just the assets + spec sheet), it should cover: logo usage rules, clear space/minimum size (from spec-sheet.md), do's/don'ts with visual examples, full color system (hex/RGB/CMYK), typography (hierarchy, licensing/web-safe fallbacks if relevant), and optionally an iconography/pattern direction if the brief calls for a fuller identity system beyond the mark itself. Use the docx or pdf skill for this if a downloadable document is wanted — this reference file only covers what content it should contain, not how to build the file itself.

## File naming convention

Keep it flat and predictable so `lf_export.py` and any future automation can find things:
```
brand/
  primary.svg
  icon.svg
  wordmark.svg
  monogram.svg              (if applicable)
  primary-horizontal.svg
  primary-stacked.svg
  variants/
    primary-black.svg
    primary-white.svg
    icon-black.svg
    icon-white.svg
    ...
  export/
    favicon.ico
    icon-16.png ... icon-512.png
    ios/  android/  social/
  spec-sheet.md
  animated/                 (if animation was in scope)
    icon-reveal.svg          (SMIL/CSS stroke-draw)
    icon-reveal.json         (Lottie, only if generated)
```
